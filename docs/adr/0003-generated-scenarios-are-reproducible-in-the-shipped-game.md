# Generated scenarios are reproducible in the shipped game

Every scenario this project generates — a run's Ancient choices, act map, first node, encounter, and combat initial state — must be exactly what a fully unlocked Slay the Spire 2 client produces for the same run seed, so that any generated scenario can be replayed by hand in the shipped game; parity constrains what the game *offers*, while which Ancient choice a scenario takes (and any nested choice it opens) is ours to make, as long as the choice is legal and recorded. Deriving Ancient choices, the map, or encounters out-of-band from the seed, and accepting simulator-only self-consistency, were both rejected: a scenario the shipped game cannot reach is not worth recording, however cheap it is to compute. The cost is that the simulator must drive the shipped game's own Ancient-room path instead of skipping it, and that acceptance must compare against the shipped game (see ADR-0001 for the fully unlocked premise this rests on).
