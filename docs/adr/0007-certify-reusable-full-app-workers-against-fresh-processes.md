# Certify reusable full-app workers against fresh processes

Full-app validation will expose a general reusable worker lifecycle, with field-by-field parity as its first adopter, because repeatedly starting the shipped game is expensive but silently carrying one run's state into the next would invalidate the oracle. Process mode is fixed at launch; a reusable worker follows a strict state machine and an explicit `start_run`/`end_run` protocol, uses `RunManager.CleanUp()` plus run-generation guards and bounded driver shutdown, and becomes poisoned after any unrecoverable lifecycle failure. Failed entries are not retried, poisoned processes are replaced only for later entries, normal parity uses one worker with a 16-entry cap, and process ownership includes half-started and descendant processes.

Reuse is the parity default only for a certified combination of game assembly, PCK, bridge lifecycle/protocol, progression-complete profile policy, and scenario set. Certification compares the full 16-entry fresh menu-start run with one reusable process whose first entry uses the menu path and whose warm entries use direct start, then repeats the first entry as a seventeenth sentinel and verifies the profile once across the complete sequence; a new game build must be certified again. Implicit teardown, fallback to the main menu, automatic entry retries, unbounded reuse, silent fallback to fresh mode, and self-certification from an ordinary reused run were rejected because each hides which lifecycle or oracle semantics produced a result.
