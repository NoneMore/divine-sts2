# Can the sim select Neow's options?

**Question:** 现在能选择涅奥选项了吗? — can a client of this repo choose the run-start Neow (涅奥) blessing options?

**Answer (short):** No on the native-sim path — the simulated run never enters the Ancient (Neow) room and there is no way to address `Neow` through the generic event API. The gap is general rather than Neow-specific: the sim never enters *any* act's Ancient room. On the full-app bridge path the plumbing exists and the real game does enter Neow, so a caller-chosen option is probably selectable there — but the bridge drops the shipped ancient-dialogue handling, so this is unverified at runtime.

**Sources**
- Decompiled game: `../sts2-src/decompiled/MegaCrit/sts2/` (Slay the Spire 2 `sts2.dll` v0.107.1, commit `59260271`). Citations starting `Core/...` or giving a bare game file name are relative to that directory.
- This repo: citations like `src/...` or `python/...` are relative to the repo root; a bare `:NNN` continues the file named just before it in the same sentence.

## 1. What the game actually does at run start

**Neow is a map node, not a pre-map room.** Every act map gets an `Ancient` node: `StartingMapPoint = new MapPoint(3, 0)` with `StartingMapPoint.PointType = MapPointType.Ancient`
(`../sts2-src/decompiled/MegaCrit/sts2/Core/Map/StandardActMap.cs:95,302`). It sits outside the 7×N grid, is *not* part of `startMapPoints` (which holds the row-1 nodes, `StandardActMap.cs:219`), and is the parent of every row-1 node (`StandardActMap.cs:230-233`). `ActMap.GetPoint`/`HasPoint` special-case it (`Core/Map/ActMap.cs:80-83,116-119`).

**Whether it is Neow or a plain monster node is decided by the Neow epoch.** `RunManager.SetStartedWithNeowFlag` sets `ExtraFields.StartedWithNeow = UnlockState.IsEpochRevealed<NeowEpoch>()` (`Core/Runs/RunManager.cs:504-507`), and `GenerateMap` downgrades the ancient node to `MapPointType.Monster` when that flag is false (`RunManager.cs:748-751`). `UnlockState.all` contains every epoch id (`Core/Unlocks/UnlockState.cs:34`), and `NeowEpoch.Id == "NEOW_EPOCH"` (`Core/Timeline/Epochs/NeowEpoch.cs:12`). Both of this repo's paths use `UnlockState.all`, so **`StartedWithNeow == true` and the act-1 ancient node stays `Ancient`** — i.e. Neow is present in the generated map in both paths.

**A real new run walks into Neow automatically.** `RunManager.EnterAct(0)` calls `NMapScreen.InitMarker(StartingMapPoint.coord)` and then `await EnterMapCoord(State.Map.StartingMapPoint.coord)` when `StartedWithNeow` (`RunManager.cs:1243-1251`). Travelling there goes through `EnterMapPointInternal(coord.row + 1 /* actFloor 1 */, MapPointType.Ancient, ...)` (`RunManager.cs:795,801-813`), and `MapPointType.Ancient => RoomType.Event` (`RunManager.cs:902-921`), so `CreateRoom` returns `new EventRoom(State.Act.PullAncient())` (`RunManager.cs:884`) — `PullAncient` is `ActModel.Ancient`, the rolled ancient (`Core/Models/ActModel.cs:247,432-434`), which for act 1 is Neow (`Core/Models/Acts/Underdocks.cs:22`, `Overgrowth.cs:26`).

**Entering the room starts the event; the options are model-side.** `EventRoom.EnterInternal` calls `EventSynchronizer.BeginEvent(CanonicalEvent, ...)` (`Core/Rooms/EventRoom.cs:59`), which calls `EventModel.BeginEvent(player, isPreFinished)` (`Core/Multiplayer/Game/EventSynchronizer.cs:101`). For ancients, `SetInitialEventState` sets the event state to `InitialDescription` + the generated options (`Core/Models/AncientEventModel.cs:209-220`), so **`CurrentOptions` is populated as soon as the room is entered** — the dialogue pages are presentation, not a gate on the model.

**Neow's option contract.** `Neow.GenerateInitialOptions` returns 2 randomly chosen positive relic options plus 1 randomly chosen curse relic option (3 total), filtered by `RelicModel.IsAllowedAtNeow` (`Core/Models/Events/Neow.cs:215-294`; restriction hook at `Core/Models/RelicModel.cs:440-443`). The filter cannot empty the list under `UnlockState.all`: the only overrides are `Kaleidoscope` (`Core/Models/Relics/Kaleidoscope.cs:24-31`) and `ScrollBoxes` (`ScrollBoxes.cs:23-30,48-54`), and, through `IsAllowed`, `MassiveScroll` (multiplayer only), `SilverCrucible` and `WingedBoots` (singleplayer only) — all satisfied by a single-player fully unlocked run. The **only** empty-option case is the modifiers branch, which returns one option per modifier exposing `GenerateNeowOption` and `Array.Empty` when there are none (`Neow.cs:280-293`); this repo's runs pass an **empty** modifier list (`src/Sts2.NativeSim.Core/PersistentNativeCombatEnvironment.cs:405`), so the 3-relic branch is the one that applies. Choosing one runs `RelicOption`'s callback: `RelicCmd.Obtain(relic, owner)` then `Done()` → `SetEventFinished(...)` (`AncientEventModel.cs:279-288`). The selection entry point is `EventOption.Chosen()` (public `Task`, `Core/Events/EventOption.cs:160-171`); options expose `IsLocked`, `WasChosen`, `IsProceed`, `Relic`, `TextKey` (`EventOption.cs:14-36`). `IsLocked` is simply `OnChosen == null` (`EventOption.cs:62,84`), so **no Neow option is ever locked**; `WasChosen` only prevents re-clicking.

The UI path is `NEventRoom.OptionButtonClicked` → `EventSynchronizer.ChooseLocalOption(index)` → `ChooseOptionForEvent` → `Chosen()` (`Core/Nodes/Rooms/NEventRoom.cs:297-313`, `Core/Multiplayer/Game/EventSynchronizer.cs:208-234,255-270`). `NEventRoom.Create` returns `null` when `TestMode.IsOn` (`NEventRoom.cs:171-176`), which is what makes headless event rooms viable. Caveat for direct calls: `EventSynchronizer.BeginEvent` fires `BeginEvent` without awaiting (`EventSynchronizer.cs:101`), and `BeforeEventStarted` awaits a heal, so a driver should poll for `CurrentOptions.Count > 0 || IsFinished` rather than reading options immediately.

**Some Neow options open a second, blocking prompt** after the relic is obtained — card select (`HeftyTablet`, `LeadPaperweight`, `NewLeaf`, `Pomander`, `PrecariousShears`, `PreciseScissors`, `ScrollBoxes`), a reward set (`Kaleidoscope`, `LostCoffer`, `SmallCapsule`, `NeowsBones`), or a bundle pick; others are automatic (`NeowsTorment`, `NeowsTalisman`, `LargeCapsule`, `ArcaneScroll`, `FishingRod`, `LeafyPoultice`, `PhialHolster`). The prompts are issued from each relic's `AfterObtained` override, which is where the blocking call sits: `HeftyTablet.cs:27`, `LeadPaperweight.cs:19`, `NewLeaf.cs:22`, `Pomander.cs:17`, `PrecariousShears.cs:24`, `PreciseScissors.cs:18`, `ScrollBoxes.cs:32` (`CardSelectCmd.FromChooseABundleScreen` at `:40`), `Kaleidoscope.cs:33`, `LostCoffer.cs:16`, `SmallCapsule.cs:13`, `NeowsBones.cs:38` (builds a `Reward` list at `:42`), all under `Core/Models/Relics/`. A headless Neow implementation must be able to answer those, not just the event option.

**A loaded ancient is pre-finished.** `EventRoom` serialises `IsPreFinished` (`Core/Rooms/EventRoom.cs:112-123`) and a loaded ancient takes `StartPreFinished()` → done page, `PROCEED` only (`AncientEventModel.cs:209-220,235-245`). Neow's blessing is therefore a *new-run-only* event; it is not something a save-loaded run re-offers.

**The game already ships a deterministic way to force a specific ancient option.** `AncientEventModel.DebugOption` (a `TextKey` substring) is applied inside `GenerateInitialOptionsWrapper`: it removes option 0 and inserts the first `AllPossibleOptions` entry whose `TextKey` contains that string (`AncientEventModel.cs:78-89,196-203`). The dev console exposes it — `ancient <name> <choice>` builds `new EventRoom(canonical) { OnStart = e => ((AncientEventModel)e).DebugOption = choice }` and calls `RunManager.EnterRoom(room)` (`Core/DevConsole/ConsoleCommands/AncientConsoleCmd.cs:41-55`). That is both a headless entry precedent (no map travel, no UI) and the cheapest route to "pick this exact Neow relic".

**Three side effects a simulation must account for when Neow is entered:**
1. When the ancient *is* Neow, `BeforeEventStarted` sets the player's HP to **0** (`if (this is Neow)` at `AncientEventModel.cs:174-177`) and then heals the missing amount; other ancients skip the zeroing and only heal (`:178-184`). At `AscensionLevel.WearyTraveler` (A2) the heal is multiplied by `0.8`, so Neow leaves the player at 80% max HP (`AncientEventModel.cs:180-184`; `Core/Entities/Ascension/AscensionLevel.cs:5-7`). A run-reset HP is therefore *overwritten* by Neow.
2. `BeforeEventStarted` is skipped for a pre-finished ancient (`isPreFinished` path).
3. The single-`PROCEED` fallback that `GenerateInitialOptionsWrapper` substitutes when `Hook.ShouldAllowAncient` is false (`AncientEventModel.cs:195-207`; `Core/Hooks/Hook.cs:2115-2125`) is **unreachable in this build**: it depends on a hook listener overriding `AbstractModel.ShouldAllowAncient`, the base implementation returns `true` (`Core/Models/AbstractModel.cs:2167-2170`) and nothing in the assembly overrides it. So a fully unlocked, modifier-free run always gets Neow's real options.

`Neow` is registered as an **ancient**, not a regular event: it is reachable via `ModelDb.AncientEvent<Neow>()` / `ModelDb.AllAncients` (`Core/Models/ModelDb.cs:161`), while `ModelDb.AllEvents` is built only from each act's `AllEvents` plus `AllSharedEvents` (`ModelDb.cs:172`), and those lists contain regular events only (`Underdocks.cs:26-38`, `ModelDb.cs:135-155`). **`Neow` is not in `ModelDb.AllEvents`.**

## 2. Native-sim path: Neow is skipped and unreachable

`run_reset` sets `_runStage = "map"` and only calls `InitializeRunMap` (`src/Sts2.NativeSim.Core/PersistentNativeCombatEnvironment.cs:186`), which runs `CombatManager.Reset(true)`, `RunManager.GenerateRooms()` and `RunManager.GenerateMap()` — **it never calls `EnterAct` or `EnterMapCoord`, and never enters a room** (`:820-828`). The run is built from `Player.CreateForNewRun(character, UnlockState.all, 1)` plus `RunState.CreateForTest(...)` + `RunManager.SetUpTest(run, NetSingleplayerGameService, true, false)` with an **empty modifier list** (`:366,404-418`). `CreateForTest` starts with `CurrentActIndex = 0` and an empty `_visitedMapCoords` (`Core/Runs/RunState.cs:29,107,112,304-317`).

Consequences, in order of importance:

- **The first legal actions are the row-1 nodes.** In stage `map`, `BuildMapActions` reads `map.startMapPoints` when `CurrentMapPoint` is null (`:773,834-845`), and the ancient node is not in `startMapPoints` (`StandardActMap.cs:219,230-233`). The ancient node at `(3,0)` is therefore never offered; `PointType` is only echoed into the action's parameters (`:841-845`).
- **Actions are validated against that list**, so a client cannot hand-force `choose_map:3:0` (`:236-237` throws `invalid_action`).
- **`event_reset` cannot address Neow.** `InitializeEventAsync` resolves the id against `ModelDb.AllEvents` (`:1153`) with `Find`, which throws `unknown_model` when absent (`:2035-2036`), and `Neow` is not in that collection (§1). So `event_reset(event_id="Neow")` fails with `unknown_model`, not with an event-mechanics error.
- **Net effect on the current baseline:** simulated runs start *after* Neow — no blessing/curse relic, and the requested `current_hp` is never overwritten by Neow's HP reset. The map the sim plays is the same one a real post-Neow run plays (row-1 nodes, `act_floor = row + 1`).
- **This is not Neow-specific: no Ancient room is ever entered, in any act.** Every act map types its own `StartingMapPoint` as `Ancient` (`StandardActMap.cs:302`) and rolls that act's ancient from the unlocked set (`Core/Models/ActModel.cs:385`), but the sim reaches later acts by `RunManager.SetActInternal(priorAct + 1)` and then goes straight back to stage `map` (`:1492-1494`), and `SetActInternal` clears the visited coordinates (`RunManager.cs:1266-1279`). So each act's map again offers only `startMapPoints` (row 1) and the act's ancient is skipped. Neow is simply the most visible instance of the gap.

What the machinery *does* already provide (so the gap is small): the event surface is generic — `choose_event` with `option_index`/`text_key`/`is_proceed`, filtered by `IsLocked`/`WasChosen` (`:1173-1183`), dispatched to `option.Chosen()` (`:1196-1210`), plus nested `_pendingChoice` card/option choices (`:245,1169`) and run-room event entry for `RoomType.Event` (`:880-884`).

**Correction to a plausible misreading:** entering the ancient node does **not** hit the `unsupported_room` branch (`:898`). The ancient's `RoomType` is `Event` (`RunManager.cs:918`), so the existing `Event` branch (`:880-884`) would pick the event off `room.LocalMutableEvent` and the existing event loop would drive it.

## 3. Full-app bridge path: plumbing exists, dialogue handling was dropped

The bridge launches the real game and patches the shipped AutoSlay room handlers (`src/Sts2.NativeSim.FullAppBridge/FullAppBridgeMod.cs:66-85`). Because the real run enters Neow (§1) and `RunMapLoopAsync` only waits for `NMapScreen.IsOpen` afterwards (`:316-318`), the run-start Neow room is the first room the patched automation meets. Option selection there is caller-driven, not random: `WaitForCoordinatorActionAsync("event", …)` returns `choose_event:<index>`, which is parsed and clicked (`:747-762`), with an out-of-range index clamped to 0 (`:756-757`).

One piece of the bridge already knows about ancients: when the map screen is open with no visited coordinates it offers the **row-0 (Ancient)** nodes as travel targets (`:327-332`), which is how later-act ancients are entered (every act map types its `StartingMapPoint` as `Ancient`, `StandardActMap.cs:302`, and only act 0 is auto-entered, `RunManager.cs:1243-1251`). That rule is the template the native sim lacks (§4, item 1).

Two concrete gaps:

1. **The patch replaces the shipped handler, which is where ancient dialogue is handled.** `HandleEventRoomAsync` is a prefix returning `false` with its own loop (`:728-732`), and that loop does `UiHelper.FindAll<NEventOptionButton>(eventRoom)` and `if (optionButtons.Count == 0) break;` with no wait (`:744-745`). The shipped `EventRoomHandler` instead detects `NAncientEventLayout` and clicks `%DialogueHitbox` until options become enabled (`Core/AutoSlay/Handlers/Rooms/EventRoomHandler.cs:254-257,301-335`); `NAncientEventLayout` only enables the option buttons on the last dialogue line (`Core/Nodes/Events/NAncientEventLayout.cs:482-499`). That code path is not reachable through the bridge.
2. **The observation carries no event identity.** `phase == "event"` produces `RoomObservationDto { RoomType = "Event" }` with `Options.Add(idx.ToString())` only (`src/Sts2.NativeSim.FullAppBridge/FullAppStateTracker.cs:394-412`), and the DTO has no event-id field (`ProtocolMessages.cs:179-188`). A client cannot tell that the pending event is Neow, nor which relics are on offer beyond positional indices.

**Why it may nevertheless work today (unverified at runtime):** option buttons are created as soon as the event state is set (`NEventLayout.AddOptions` → `NEventOptionButton.Create` + `AddChildSafely`, `Core/Nodes/Events/NEventLayout.cs:379,389-390`) and connect their signals in `_Ready` (`NEventOptionButton.cs:282-322`). `UiHelper.Click` calls `ForceClick()`, which emits the `Released` signal unconditionally, bypassing `_isEnabled` and visibility (`Core/AutoSlay/Helpers/UiHelper.cs:17-21`; `Core/Nodes/GodotExtensions/NClickableControl.cs:554-557`), and `UiHelper.FindAll` does not filter on visibility (`UiHelper.cs:26-34`). The one remaining guard is the handler's own `if (Option.IsLocked)` early-return (`NEventOptionButton.cs:362`), and Neow's options are never locked (§1). So the bridge loop can plausibly find and force-click a Neow option while its dialogue is still on screen. That is static reasoning only; it has not been observed.

## 4. Verdict

| Capability | Native sim | Full-app bridge |
|---|---|---|
| Observe that a Neow choice is pending | **No** — no stage ever enters Neow (`PersistentNativeCombatEnvironment.cs:186,820-828`) | **Partial** — `phase == "event"` with positional options, no event identity (`FullAppStateTracker.cs:394-412`) |
| Select a specific, caller-chosen Neow option | **No** — no path reaches a `Neow` instance; `event_reset` id lookup excludes it (`:1153`; `ModelDb.cs:172`) | **Probably yes** — `choose_event:<index>` is caller-driven (`FullAppBridgeMod.cs:747-762`), but ancient-dialogue handling was dropped (`:744-745`) |
| Select *some* Neow option (any/first legal) | **No** — same reason | **Probably yes**, index 0 fallback (`:756-757`) |

### Minimal change list to make the native sim answer "yes"

1. Offer the ancient node as a legal map action at run start — e.g. include `map.StartingMapPoint` when `CurrentMapPoint` is null and its `PointType == Ancient`, so `choose_map:3:0` becomes legal and routes through the existing `EnterRunMapCoordAsync` (`:855-899`). The full-app bridge already applies exactly this rule (`FullAppBridgeMod.cs:327-332`), and `MapPointType.Ancient` already produces `RoomType.Event` (`RunManager.cs:918`) and `EventRoom(PullAncient())` (`:884`), so the existing `Event` branch (`:880-884`) then drives Neow with no new room coordinator.
2. Or skip the map and auto-enter the ancient node in `InitializeRunMap`, mirroring `EnterAct(0)` (`RunManager.cs:1243-1251`), or enter the event directly with `RunManager.EnterRoomDebug(RoomType.Event, MapPointType.Ancient, ModelDb.AncientEvent<Neow>())` (`RunManager.cs:990-1034`, model override consumed at `:884`) — the same route the shipped `AncientConsoleCmd` uses (`Core/DevConsole/ConsoleCommands/AncientConsoleCmd.cs:45-55`).
3. Decide how Neow's HP reset interacts with the reset request: entering Neow sets HP to full (or 80% at A2) via `BeforeEventStarted` (`AncientEventModel.cs:170-191`), so the reset's `current_hp` is overwritten. Either accept that or re-apply the requested loadout afterwards.
4. Answer the second-stage prompts that several options open (card select / reward set / bundle pick — see §1), or restrict the offered options to the automatic ones for a first cut.
5. For deterministic selection, prefer `AncientEventModel.DebugOption` (set a `TextKey` substring before the event begins, `AncientEventModel.cs:196-203`) over index picking — it survives option-list reordering and matches the shipped dev-console behaviour (`AncientConsoleCmd.cs:41-55`).
6. Optionally make `event_reset` accept ancients by falling back to `ModelDb.AllAncients` (`ModelDb.cs:161`) when `AllEvents` has no match (`:1153`), which would allow studying the option roll in isolation. Note `event_reset`'s current `BeginEvent(player, false)` hard-codes `isPreFinished = false` (`:1163`), which is the correct value for a fresh Neow.
7. Add acceptance coverage: no script under `python/` currently references Neow or a run-start ancient choice (`run_event_acceptance.py`, `run_room_cycle_acceptance.py`, `full_app_unlock_acceptance.py` cover only regular events).

### Unknowns / how to settle them empirically

- Whether the full-app bridge's force-click on a mid-dialogue ancient option actually completes the Neow flow end-to-end (needs one real bridged run; watch `autoplay_<seed>.log`).
- Whether `Neow.GenerateInitialOptions`'s RNG draws shift run RNG parity once the ancient room consumes `Rng` (`Neow.cs:215-294`) — the sim's `seed`/`rng_counters` observation would change for the same seed if Neow starts being entered.
- Whether the nested prompts above resolve inside the native sim's `_pendingChoice`/`RewardsSet` plumbing without a real Godot tree (the sim's blocking-choice wiring is at `PersistentNativeCombatEnvironment.cs:2228,2256,2422`).

## Update: unknown 2 (RNG parity) is answered — no

Neow's option roll does **not** shift run RNG parity, so that unknown is closed: `EventModel.BeginEvent` gives the event its own `Rng` (`Core/Models/EventModel.cs:238`), keyed on the run seed + player slot + `hash(eventId)`, and `Neow.GenerateInitialOptions` draws only from that instance (`Core/Models/Events/Neow.cs:215-294`). No `RunRngSet` counter moves, so the `seed`/`rng_counters` observation cannot change merely by starting to enter Neow. The parity hazards that this note missed are elsewhere — see `../act1-combat1-scenarios/parity-findings.md` (`TotalFloor`, and the rolled act-1 variant).
